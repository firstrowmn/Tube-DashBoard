# API передачи телеметрии качества связи

Документ для Новосибирского метрополитена. Версия API: `v1`.

## Назначение и периодичность

После завершения каждого пятиминутного цикла ping система метрополитена отправляет один пакет с результатами по всем контролируемым устройствам. Рекомендуемая периодичность — один пакет каждые 5 минут.

Время передаётся в ISO 8601 с часовым поясом Новосибирска `+07:00`. Поле `measuredAt` — время окончания пятиминутного замера.

## Запрос

```text
POST https://<адрес-api>/api/v1/link-loss
Content-Type: application/json; charset=utf-8
X-API-Key: <выданный-секретный-ключ>
```

Максимальный размер тела — 2 МБ, максимальное число измерений в пакете — 5000.

```json
{
  "source": "novosibirsk-metro",
  "generatedAt": "2026-08-31T17:30:05+07:00",
  "measurementWindowSeconds": 300,
  "measurements": [
    {"deviceId":"TID-123456","ip":"10.20.30.41","lossPercent":4.7,"measuredAt":"2026-08-31T17:30:00+07:00"},
    {"deviceId":"TID-123457","ip":"10.20.30.42","lossPercent":18.2,"measuredAt":"2026-08-31T17:30:00+07:00"}
  ]
}
```

## Поля

| Поле | Тип | Обязательное | Требования |
|---|---|---:|---|
| `source` | string | да | строго `novosibirsk-metro` |
| `generatedAt` | string | да | время формирования пакета, ISO 8601 с `+07:00` |
| `measurementWindowSeconds` | integer | да | строго `300` |
| `measurements` | array | да | от 1 до 5000 элементов |
| `measurements[].deviceId` | string | да | стабильный TID, 1–128 символов; допустимы буквы, цифры, `. _ : -` |
| `measurements[].ip` | string | нет | контрольное поле, до 64 символов |
| `measurements[].lossPercent` | number | да | процент потерь от `0` до `100` включительно |
| `measurements[].measuredAt` | string | да | окончание замера, ISO 8601 с `+07:00` |

Основной идентификатор оборудования — `deviceId`/TID. IP не используется как первичный ключ и может меняться.

## Успешный ответ

HTTP `202 Accepted`:

```json
{"status":"accepted","accepted":2,"duplicates":0,"receivedAt":"2026-08-31T10:30:06.218Z"}
```

Повторная безопасная отправка разрешена. Измерение с уже принятой парой `deviceId + measuredAt` не записывается второй раз и учитывается в `duplicates`.

## Ошибки

| HTTP | Значение | Действие отправителя |
|---:|---|---|
| `400` | повреждённый JSON | исправить формирование JSON, не повторять без изменения |
| `401` | неверный или отсутствующий API-ключ | проверить `X-API-Key` |
| `413` | пакет больше 2 МБ | уменьшить пакет |
| `422` | ошибка проверки полей | исправить поля по массиву `details` |
| `500` | внутренняя ошибка | повторить с задержкой |
| `503` | API не настроен | обратиться к администратору API |

Пример ошибки проверки, HTTP `422`:

```json
{"error":"validation_error","details":["measurements[0].lossPercent must be between 0 and 100"]}
```

При сетевой ошибке или ответе `500` рекомендуется выполнить до 5 повторов с интервалами 10, 30, 60, 120 и 300 секунд. Повторы не создают дубликаты. При ответах `400`, `401`, `413`, `422` автоматические повторы без исправления запроса не нужны.

## Логика отображения

- `0 ≤ lossPercent ≤ 10` — зелёный;
- `10 < lossPercent ≤ 30` — жёлтый;
- `lossPercent > 30` — красный;
- если последнее `measuredAt` старше 12 минут или данных ещё нет — серый.

## Требования безопасности

Передача выполняется только по HTTPS. API-ключ должен храниться как секрет, не записываться в исходный код и не передаваться в URL. Рекомендуются VPN или список разрешённых исходящих IP метрополитена. Для согласования интеграции администратор API передаёт метрополитену фактический URL, API-ключ и при необходимости сертификат/сетевые параметры.

# Развёртывание backend

API реализован на Node.js 20+ без внешних библиотек. Он может одновременно обслуживать дашборд и API либо работать отдельно от GitHub Pages.

## Настройки

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `PORT` | порт HTTP-сервера | `8080` |
| `METRO_API_KEY` | обязательный секрет для приёма POST | отсутствует |
| `DATA_DIR` | каталог постоянного хранения | `.data` |
| `CORS_ORIGIN` | разрешённый адрес фронта | `*` |

Пример запуска в PowerShell:

```powershell
$env:METRO_API_KEY = '<случайный-секрет-не-менее-32-символов>'
$env:DATA_DIR = 'D:\metro-telemetry'
$env:CORS_ORIGIN = 'https://firstrowmn.github.io'
node server/index.js
```

В production сервис должен находиться за HTTPS reverse proxy. Каталог `DATA_DIR` должен быть на постоянном диске и включён в резервное копирование. Один каталог нельзя одновременно подключать к нескольким экземплярам API. Для горизонтального масштабирования следует заменить файловое хранилище на PostgreSQL.

История хранится в `history.ndjson`, последние значения — в `latest.json`. Записи истории дедуплицируются по паре `deviceId + measuredAt`.

## Подключение GitHub Pages

В `config.js` указать публичный HTTPS-адрес API:

```js
window.METRO_API_BASE_URL = 'https://api.example.ru';
```

В `data/equipment.json` каждому реальному АКП необходимо задать стабильный `deviceId`, совпадающий с TID в телеметрии. IP является дополнительным контрольным полем.

## Проверка работоспособности

- `GET /api/v1/health` — состояние процесса;
- `GET /api/v1/telemetry/latest` — последние значения;
- `GET /api/v1/telemetry/history?deviceId=TID-123&limit=100` — история.

API возвращает серый статус, если `measuredAt` старше 12 минут. Фронт повторяет эту проверку, чтобы статус менялся даже при временной недоступности API.
